# Inverted Pendulum

This project implements an inverted pendulum system using Arduino. The inverted pendulum is a classic problem in dynamics and control theory, where a pendulum is balanced on its pivot point, and the goal is to keep it upright.

## List of components:

- NEMA 17 Stepper Motor
- Rotary Encoder E38S6G5-600B-G24N
- Arduino Uno R3
- Stepper Motor Driver A4988
- 1x Resistor (200 Ω)

- Capacitor (10 uF)

## How to Operate

The system is controlled via the Arduino Serial Monitor. The pendulum has a strict safety mechanism and requires calibration before starting the control loop.

**Startup Sequence:**
1. Let the pendulum hang freely pointing straight down (its stable rest position).
2. Send `ZERO_DOWN` via the Serial Monitor. The system will calibrate this as the 0° reference.
3. Manually raise the pendulum to the perfectly upright position. **Be careful to hold it steady and avoid any sudden movements**.
4. Send `START` to engage the PID control and enable the stepper motor.

### Real-time PID Tuning

You can tune the PID values on the fly without recompiling the code. Use the following command format in the Serial Monitor:

`PID <Kp> <Ki> <Kd> <Bias>`

*Example:* `PID 0.009 3.00 0.002 0.00`

> **Note on effective gains:** Because the code calculates velocity as ΔAngle / Δtime (where the control loop dt = 0.002s), the actual applied physical gains are mathematically multiplied by a factor of 500. For instance, a Kp of `0.009` effectively acts as a proportional gain of `4.5`.

**Emergency Stop:** 
Send `STOP` at any time to safely disable the motor.

## Troubleshooting & Tips

* **Encoder Missing Steps / Drifting:** Industrial NPN Open-Collector encoders (like the E38S6G5) require strong external pull-up resistors. Ensure you have ~2.2kΩ to 5kΩ resistors connected between the encoder's Phase A/B signal wires and the 5V line. The internal Arduino `INPUT_PULLUP` is not fast/strong enough for high-speed switching, causing dropped counts.

* **Continuous Drift to One Side:** If the motor balances the pendulum but slowly "walks" towards the end of the rail, check your integral gain (`Ki`) and your encoder wires. Mechanical tension from stiff wires tricks the integral term into accumulating error to fight the wire's spring force.

* **Power Supply Filtering:** Add capacitors, such as a 10uF electrolytic or higher, on the 12V power supply line and close to the motor driver to stabilize the system and mitigate electrical noise generated by motor switching.

* **PID Gain Behavior:**
* Excessively high Kp values cause the motor to respond with extreme and aggressive speed.
* Very high Kd values induce intense motor vibrations and over-rigid system behavior.
* Increasing Ki was crucial for stabilizing this specific context, but fine-tuning must be evaluated case-by-case.
* The Bias parameter remained untouched throughout all tests and proved unnecessary to modify.

* **Rod Physical Variables:** The height, length, and weight of the rod attached to the encoder shaft directly impact system dynamics, altering inertia and requiring a complete re-evaluation of control calculations.
